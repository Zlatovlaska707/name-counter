# name-counter

Консольная утилита на **Go 1.22**, которая читает текстовый файл (**одна строка = одна метка**, обычно «имя»), в кодировке **UTF-8**, и печатает в **stdout**, сколько раз встречается каждая **уникальная** непустая строка.

Файл читается **потоково** (построчно), поэтому размер входного файла на диске может быть очень большим. Ограничение по памяти связано с числом **уникальных** строк.


---

## Кратко: что на выходе

- **stdout** — строки вида `строка: число` (по одной на каждую уникальную метку после `TrimSpace`).
- **stderr** — сообщения об ошибках, предупреждения, логи (в том числе pprof и ожидание завершения после основной работы).

Пример для `testdata/sample.txt` при сортировке по умолчанию (`freq`):

```text
Алёна: 2
Дима: 1
Миша: 1
```

## Сборка и установка

Точка входа основной программы: каталог [`cmd/run`](cmd/run) (модуль `main`).

### Сборка в бинарник в текущем каталоге

```bash
go build -o namecounter ./cmd/run
```

Имя файла на ваш выбор, например `run` или `namecounter.exe` на Windows:

```powershell
go build -o namecounter.exe ./cmd/run
```

### Запуск без предварительной сборки

```bash
go run ./cmd/run путь/к/файлу.txt
```

Флаги основной программы указывайте **сразу после** `./cmd/run` (в одном списке аргументов для `go run`). Для этого модуля это обычно работает без специального разделителя:

```bash
go run ./cmd/run -file testdata/sample.txt -sort name
```

**Важно:** не передавайте в программу отдельный аргумент `--` перед флагами. Стандартный `flag.Parse()` воспринимает `--` как «конец флагов»; дальнейшие токены вроде `-file` уже не будут разобраны как флаги, и путь к файлу не подхватится.

Позиционный путь:

```bash
go run ./cmd/run testdata/sample.txt
```



(из корня модуля при разработке обычно достаточно `go install ./cmd/run`.)

## Коды завершения

| Код | Когда |
|-----|--------|
| **0** | Успех: файл обработан, результат выведен; или показана справка `-help`. |
| **1** | Ошибка выполнения: не открыть файл, ошибка чтения/сканирования, ошибка записи в stdout и т.п. |
| **2** | Ошибка использования: не указан файл, неверный `-sort`, сбой разбора флагов. |

---

## Формат вывода

Каждая строка:

```text
<строка>: <целое неотрицательное>
```

После числа — символ новой строки `\n`. Порядок строк задаётся `-sort`.

---

## Сортировка результатов

### `freq` (и синоним `frequency`) — по умолчанию

1. Сначала **большая** частота.
2. При **равной** частоте — **лексикографически по возрастанию** имени (как сравнение строк в Go, байтовое представление UTF-8).

### `name`

Сортировка **только по имени** (лексикографически по возрастанию), частота на порядок не влияет.

Любое другое значение `-sort` даёт ошибку и **код 2**.

## Профилирование (pprof)

При **непустом** `-pprof` поднимается HTTP-сервер со стандартными маршрутами из [`net/http/pprof`](https://pkg.go.dev/net/http/pprof).

Примеры URL (для `-pprof :6060` на той же машине):

- обзор: `http://127.0.0.1:6060/debug/pprof/`

**Поведение после подсчёта:** если pprof был включён, основная работа завершается, но процесс **не выходит сразу**: в лог пишется, что сервер pprof ещё работает, и программа ждёт **SIGINT** или **SIGTERM**, затем корректно останавливает HTTP-сервер. Это удобно для снятия профиля **после** прохода по файлу.
